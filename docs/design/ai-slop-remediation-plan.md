# 脱・AIスロップ デザイン改修計画（2026-06-11）

立案: 独立デザインディレクターエージェント（実装・監査に非関与）。
指摘の出典: `ai-slop-audit-findings.md`（A/B/C 計34件）。

## 1. デザインコンセプトの再定義

**根本原因の診断:** 「素材を一律のルールで均す」設計 — system-ui任せのフォント、全要素同一の金色＋大文字ラベル、機械的2倍刻みgap、根拠なき角丸ばらつきが「テンプレに値を流し込んだ」印象を生んでいる。

**目指す視覚アイデンティティ: 「点棒箱の上に置いた手書きスコアシート」**。
雀荘で実際に使う紙の精算表の文法 — 罫線で区切られた格子、太字の数字、右揃えの金額、最下行の合計 — を設計言語にする。装飾としての「和＝金」をやめ、**緑のラシャ卓＋生成り紙＋朱（負け）と墨（勝ち）の対比**を機能色として使う。金色は「店に払う額」など店との金銭境界1箇所だけのアクセントに格下げ。

> **改訂（2026-06-11、P2実装時のユーザー指示）:** 地色を「深緑の卓」から**白基調（生成りの紙 #f3efe5）に全面変更**。紙のスコアシートのメタファーを地色まで徹底し、深緑 #1d5c45 は primary ボタン・アクティブ選択・プラス収支の差し色に格下げ。マイナス収支は朱 #b3402f、本文は墨 #2f2c25、店払い見出しは茶金 #8a6d2a。実装済みトークンの正本は `src/index.css` の `:root`。

## 2. 対応方針（クラスタ別）

### クラスタ1: フォント体系（A-4, B-1, B-2, C-3）— P1 / 工数S
- 見出し（ディスプレイ）: **Zen Old Mincho**（400,700）— 紙の帳簿感
- 本文・UI: **Zen Kaku Gothic New**（400,500,700）
- 数字（点数・金額）: **DM Mono**（400,500）+ tabular-nums
- ```css
  --font-display: 'Zen Old Mincho', serif;
  --font-sans: 'Zen Kaku Gothic New', system-ui, sans-serif;
  --font-mono: 'DM Mono', 'Roboto Mono', ui-monospace, monospace;
  ```
- index.html に preconnect×2 + 単一 css2 link、`display=swap`
- ⚠️ 和文3ファミリで初回 0.5〜1.5MB。明朝はタイトル/見出しのみに限定。重ければ「本文1+mono1」の2ファミリに縮退可

### クラスタ2: 配色・金色の格下げ（A-1, A-5, A-6, A-7, A-8）— P1〜P2 / 工数M
- 背景: ほぼ同色グラデを廃止 → ソリッド `#0d3a2c` + 極薄のラシャ目テクスチャ（repeating-linear-gradient 1px）。擬似要素1枚に乗せる（background-attachment: fixed 禁止 / iOS Safari でジャンク）
- 麻タイル: 3層shadow → 2層（厚み1段+落ち影1段）。inset光沢を削除し紙牌の質感に
- タイトルの金色廃止 → 生成りの明朝
- **金色の新ポリシー: 「店に払う額」とアクティブ選択のみ**。勝ち負けは朱/墨、構造は罫線

### クラスタ3: インタラクション語彙（A-2, A-3）— P3 / 工数S
- 押下表現を種別で分ける: primary=translateY(1px)+影縮小の「押し込み」、segment=scale(0.97)維持、ghost=背景濃度のみ
- モバイル主用途のため hover より :active と :focus-visible を優先

### クラスタ4: ホーム画面の構造（C-1, A-11, B-3, B-4, B-5）— P2 / 工数M
- 中央寄せヒーロー廃止 → 「帳面を開く」レイアウト（上: 前回卓カード=名前・局数・収支幅が主役、下: 新規開始）
- 文言: サブタイトル削除（罫線に置換）／「新しいゲームを始める」→**「卓を立てる」**／「続きから再開」→**「つづきを開く」**＋前回情報を本文化
- 「←」→ CSS三角 or SVGチェブロン

```
┌─────────────────────────────┐
│   麻雀清算           [明朝・生成り] │
│  ─────────────────────────── │
│  前回の卓                      │
│  ┌──────────────────────┐   │
│  │ 田中・佐藤・鈴木・山田    │   │
│  │ 3局 / +12,000 〜 -8,000│   │
│  │           [つづきを開く →]│   │
│  └──────────────────────┘   │
│  [ 卓を立てる ]                │
└─────────────────────────────┘
```

### クラスタ5: カード・角丸・余白の体系化（A-8, C-4, C-5, C-6）— P2 / 工数M
- 角丸を2値に固定: `--radius-card: 4px`（紙の角）/ `--radius-control: 8px`（押す部品）。ボトムシート上角のみ例外可
- カード5変種 → 単一 `.sheet` クラス（帳面の区画）に統合
- card-in-card（累計収支）→ 罫線区切りのグリッドへ
- spacing を 4の倍数スケールに縮約: `--space-1..5: 4/8/12/16/24`（48は画面余白のみ）
- 罫線トークン: `--rule: 1px solid rgba(201,164,92,.22)`

### クラスタ6: セクションラベルの脱・量産化（A-7, B-8, C-8）— P2 / 工数S
- uppercase+letter-spacing+金/灰 を全廃 → 「罫線+明朝の小見出し」`.sheet-title`（15px/700/生成り/border-bottom）
- 見出し階層を**ファミリ（明朝↔ゴシック）とサイズ**で構築: ホーム28明朝 / 画面20明朝 / 区画15明朝 / ラベル13ゴシック。13px未満に明朝は使わない

### クラスタ7: コピー・文言（B-6, B-7, B-9〜B-13）— P1(B-10,B-12)〜P2 / 工数S

| Before | After |
|---|---|
| プレイヤー1の名前を入力してください。 | 1席の名前が空です |
| プレイヤー名が重複しています。 | 同じ名前が2人います |
| カスタムレートに正の数を入力してください。 | レートは1以上で |
| ゲーム設定 | 卓の設定 |
| 累計収支 | ここまでの収支 |
| 送金指示 | 精算 — だれがだれに |
| 収支内訳 | 収支のうちわけ |
| 入力中（ドラフト行） | 今局（または「次の局」） |
| 送金なし（全員±0） | 貸し借りなし。きれいに終局 |
| text-transform: uppercase（日本語） | プロパティ削除（デッドコード） |
| title「麻雀清算」 | 麻雀清算 — 仲間内の精算メモ |

- トーン: 内輪で通じる最小限の麻雀語彙。スラング（ツモる等）は不使用。エラーは `role="alert"` の読み上げで対象が残る形に

### クラスタ8: 設定画面の重要度設計（C-2, C-10）— P2 / 工数M
- 必須2項目（プレイヤー名・レート）を大きく上部・強罫線、ルール詳細（ウマ/オカ/場代分担）は一段落とした副次グループ（インデント+弱罫線、デフォルト展開のまま。折りたたみはP3）
- オカボタンから長文説明を分離: ボタンは「あり/なし」のみ、補足は区画ノートに1行

### クラスタ9: 清算画面のクライマックス演出（A-9, C-7, C-9）— P1(順序)〜P2 / 工数L
- カード順を **送金→店→内訳** に再構成（現状は山が最後に埋もれる）
- 送金1件を「伝票の1行」に: 名前チップ＋CSS引き線（border+三角擬似要素）＋金額を主役に大きく右揃え
- スクショ1枚で完結する精算票として設計: 不透明背景・右揃え・tabular・太字金額。「店へ払う」に金色を集中
- 収支内訳は P2 で `<details>` 折りたたみ（検算需要は副次）

### クラスタ10: エラー表示（A-10）— P3 / 工数S
- 左ボーダー紋切り型 → 点数表の文脈で「該当セルの罫線を朱に+行頭朱点」。色だけに頼らずテキスト併記（色覚配慮、対応時必須）

## 3. やらないことリスト
- 牌の3Dレンダリング・SVG牌イラストの量産（装飾過多への逆振り禁止）
- ページ遷移の派手なアニメーション/パララックス
- 金色を増やす方向の「和風リッチ化」、金屏風・市松・青海波等の和柄テクスチャ（クリシェ）
- 清算画面の紙吹雪・勝者煽り演出（内輪の金銭精算に不適切）
- オノマトペ/スラング全開のコピー
- 点数表の入力体験の作り替え（今回は見た目のみが範囲）
- フォント3ファミリ超への拡張

## 4. 実装ロードマップ

各ステップは1段階ずつ視覚確認できる単位。検証は375px幅スクショを docs/verification/ に保存して前後比較。

| Step | 内容 | 優先度 | 検証 |
|------|------|--------|------|
| 1 | フォント差し替え（クラスタ1） | P1 | 4画面スクショ＋Network で読込重量（初回1.5MB以下） |
| 2 | 金色格下げ＋麻タイル/タイトル質感（A-5,A-6） | P1 | ホームスクショ |
| 3 | コピー一括修正（クラスタ7） | P1 | 文言チェックリスト照合 |
| 4 | 清算画面の順序入替＋送金ヒーロー化（C-7） | P1 | 清算スクショ「最初に目に入るのが送金額」か |
| 5 | 寸法トークン導入・カード統合（クラスタ5） | P2 | 全画面で角丸/余白の散らばり解消 |
| 6 | セクション見出しの罫線化（クラスタ6） | P2 | 見出しスクショ |
| 7 | ホーム画面再構成（クラスタ4） | P2 | savedGameあり/なし両状態 |
| 8 | 設定画面の重要度設計（クラスタ8） | P2 | 視覚差・押下面積分離 |
| 9 | 清算の伝票レイアウト＋内訳折りたたみ（クラスタ9残） | P2 | スクショ共有想定で1枚に収まるか |
| 10 | インタラクション語彙＋エラー表示（クラスタ3,10） | P3 | 押下/エラー状態、色覚シミュレータ |

**核心:** 34件の根本は「素材を一律ルールで均した」こと1点。対策は**紙のスコアシートという単一の設計言語**に全クラスタを従わせる — フォントは帳簿の明朝、構造は罫線の格子、色は朱と墨の対比、金は店との金銭境界のみ。**P1（Step 1-4）だけで AI っぽさの大半は消える。**
